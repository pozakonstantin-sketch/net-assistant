# Telegram-бот

Пульт к ядру ассистента прямо в Telegram: пишете боту текстом или голосом —
он управляет ПК, телефоном и роутером. Работает **через long polling**, поэтому
входящие порты открывать не нужно: ВМ сама ходит на `api.telegram.org`.

## Схема

```
Telegram  ──►  api.telegram.org  ──►  ВМ: core.telegram_bot  ──►  ядро (/chat)
                                             │                      │
                                        кнопки «Подтвердить»    ПК / телефон / роутер
```

Бот не содержит логики управления: он только пересылает текст в `/chat` ядра,
показывает кнопки подтверждения опасных действий и присылает скриншоты.

## Установка

1. **Создать бота.** В Telegram напишите [@BotFather](https://t.me/BotFather):
   ```
   /newbot
   ```
   Придумайте имя и username (должен заканчиваться на `bot`). BotFather пришлёт
   токен вида `123456789:AAE...`.

2. **Вписать токен в `.env` на ВМ:**
   ```bash
   sudo nano /opt/net-assistant/.env
   # TELEGRAM_BOT_TOKEN=123456789:AAE...
   ```

3. **Запустить бота:**
   ```bash
   sudo systemctl enable --now net-assistant-telegram
   sudo systemctl status net-assistant-telegram
   ```

4. **Узнать свой chat_id.** Напишите боту любое сообщение — он ответит:
   > ℹ️ Ваш chat_id: `123456789`

5. **Закрыть доступ** — впишите id в `.env` и перезапустите:
   ```bash
   # TELEGRAM_ALLOWED_CHAT_IDS=123456789
   sudo systemctl restart net-assistant-telegram
   ```
   > Пока список пуст, бот **не выполняет** команды ни от кого: он только
   > подсказывает chat_id. Так чужой человек не получит доступ к вашему ПК.

## Как пользоваться

Просто пишите задачу обычными словами:

| Сообщение | Что произойдёт |
|---|---|
| Какая температура телефона? | `battery.status` на телефоне |
| Сделай скриншот ПК | `sys.screenshot`, бот пришлёт картинку |
| Кто подключён к роутеру? | `router.clients` |
| Выключи WiFi на роутере | запросит подтверждение кнопкой |
| Поставь громкость 30% | `media.volume` на ПК |

Голосовое сообщение распознаётся (если настроен STT — `STT_ENGINE`) и
выполняется как обычная реплика.

### Команды

| Команда | Действие |
|---|---|
| `/status` | ядро, модель ИИ, список устройств |
| `/pending` | что ждёт подтверждения (с кнопками) |
| `/reset` | очистить контекст диалога |
| `/help` | справка |

### Подтверждения

Опасные действия (`exec.run`, `fs.write`, `fs.delete`, `power.action`,
перезагрузка роутера, отправка SMS…) не выполняются сразу. Бот присылает
кнопки **✅ Подтвердить** / **❌ Отмена**, либо можно написать
`подтверждаю <токен>`.

Токен живёт 10 минут.

## Обслуживание

```bash
journalctl -u net-assistant-telegram -f      # логи
sudo systemctl restart net-assistant-telegram
```

Если бот молчит:

1. `systemctl is-active net-assistant-telegram` — процесс жив;
2. в логах `getUpdates` — есть ли доступ к `api.telegram.org` из ВМ;
3. `TELEGRAM_ALLOWED_CHAT_IDS` содержит ваш chat_id;
4. токен не занят другим процессом (Telegram отдаёт `409 Conflict`, если
   один токен опрашивают из двух мест).

## Безопасность

- Токен бота и общий `ASSISTANT_TOKEN` лежат в `.env` (не в git, режим `600`).
- Разрешённые чаты задаются явно; при пустом списке бот не выполняет команды.
- Всё, что бот делает, попадает в журнал ядра: `data/audit.jsonl`.
- Бот и ядро живут на одной машине и общаются по `127.0.0.1`, наружу
  трафик к устройствам не идёт.
- Если токен утёк — BotFather `/revoke` и новый токен в `.env`.
