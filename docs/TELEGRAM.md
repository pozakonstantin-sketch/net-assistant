# Telegram-бот

Пульт к ядру ассистента прямо в Telegram: пишете боту текстом или голосом —
он управляет ПК, телефоном и роутером. Работает **через long polling**, поэтому
входящие порты открывать не нужно: ВМ сама ходит на `api.telegram.org`.

## Схема

```
Telegram  ──►  api.telegram.org  ──►  ВМ: core.telegram_bot  ──►  ядро (/chat)
                                             │                      │
                                        кнопки «Подтвердить»    ПК / телефон / роутер
```

Бот не содержит логики управления: он только пересылает текст в `/chat` ядра,
показывает кнопки подтверждения опасных действий и присылает скриншоты.

## Установка

1. **Создать бота.** В Telegram напишите [@BotFather](https://t.me/BotFather):
   ```
   /newbot
   ```
   Придумайте имя и username (должен заканчиваться на `bot`). BotFather пришлёт
   токен вида `123456789:AAE...`.

2. **Вписать токен в `.env` на ВМ:**
   ```bash
   sudo nano /opt/net-assistant/.env
   # TELEGRAM_BOT_TOKEN=123456789:AAE...
   ```

3. **Запустить бота:**
   ```bash
   sudo systemctl enable --now net-assistant-telegram
   sudo systemctl status net-assistant-telegram
   ```

4. **Узнать свой chat_id.** Напишите боту любое сообщение — он ответит:
   > ℹ️ Ваш chat_id: `123456789`

5. **Закрыть доступ** — впишите id в `.env` и перезапустите:
   ```bash
   # TELEGRAM_ALLOWED_CHAT_IDS=123456789
   sudo systemctl restart net-assistant-telegram
   ```
   > Пока список пуст, бот **не выполняет** команды ни от кого: он только
   > подсказывает chat_id. Так чужой человек не получит доступ к вашему ПК.

## Как пользоваться

Просто пишите задачу обычными словами:

| Сообщение | Что произойдёт |
|---|---|
| Какая температура телефона? | `battery.status` на телефоне |
| Сделай скриншот ПК | `sys.screenshot`, бот пришлёт картинку |
| Кто подключён к роутеру? | `router.clients` |
| Выключи WiFi на роутере | запросит подтверждение кнопкой |
| Поставь громкость 30% | `media.volume` на ПК |

Голосовое сообщение распознаётся (если настроен STT — `STT_ENGINE`) и
выполняется как обычная реплика.

### Команды

| Команда | Действие |
|---|---|
| `/status` | ядро, модель ИИ, список устройств |
| `/pending` | что ждёт подтверждения (с кнопками) |
| `/panel` | открыть панель (мини-приложение) |
| `/reset` | очистить контекст и историю диалога |
| `/help` | справка |

### Подтверждения

Опасные действия (`exec.run`, `fs.write`, `fs.delete`, `power.action`,
перезагрузка роутера, отправка SMS…) не выполняются сразу. Бот присылает
кнопки **✅ Подтвердить** / **❌ Отмена**, либо можно написать
`подтверждаю <токен>`.

Токен живёт 10 минут.

## Панель: Telegram и браузер

Панель — один веб-интерфейс с двумя раскладками:

- **мини-приложение Telegram** — мобильный интерфейс: верхняя строка, нижняя
  навигация, чат пузырями, шторки и диалоги. Вход без пароля по `initData`,
  сессия `tg-<user_id>` — та же переписка, что и у бота;
- **браузер** — десктопный интерфейс: слева сайдбар (навигация, статус, список
  устройств с индикаторами), справа широкий чат; на узком окне включается
  мобильная раскладка. Вход по токену ассистента, отдельная сессия `web-<id>`.

Экраны одинаковые: **Чат**, **Устройства** (прямая команда), **Журнал**
(подтверждения + аудит), **Ещё** (выбор модели ИИ, очистка истории, смена
токена, озвучка).

Переписка хранится на ядре — `data/history/<session>.jsonl` — и подгружается
при открытии через `GET /history`, поэтому перезагрузка страницы или перезапуск
ядра её не теряют. Очистка — кнопкой «Очистить историю» в панели или
`DELETE /session/<session>` (в боте — `/reset`).

Telegram требует **HTTPS** для мини-приложения, поэтому панель публикуется
через Tailscale Serve — сертификат Let's Encrypt выдаётся автоматически.

### Где запускать Serve

По умолчанию Serve работает **на ВМ**: там же, где ядро, поэтому проксирование
локальное, без лишних хопов, а за соединением `tailscaled` следит
`tailscale-watchdog.timer`.

```bash
# на ВМ (ядро слушает 127.0.0.1:8787)
sudo tailscale serve --bg --https=443 http://127.0.0.1:8787
sudo tailscale serve status
```

Если `tailscaled` в ВМ начнёт терять управляющее соединение (домашняя сеть
рвёт долгие TCP-сессии), Serve можно переставить на ПК и проксировать на ядро
по локальной сети:

```
Telegram → https://desktop-isuob1d.taile4385b.ts.net → http://192.168.1.161:8787 (ядро в ВМ)
```

```powershell
# на ПК (Windows):
tailscale serve --bg --yes --https=443 http://192.168.1.161:8787
tailscale serve status
```

Нужны две галочки в админке Tailscale (один раз на весь tailnet):

1. **Serve** — `https://login.tailscale.com/f/serve?node=<узел>`
2. **HTTPS Certificates** — `https://login.tailscale.com/admin/dns`

Адрес для `.env` — DNS-имя того узла, где запущен Serve:

```env
TELEGRAM_WEBAPP_URL=https://astra-hub.taile4385b.ts.net
```

После перезапуска бот сам ставит кнопку **«Панель»** у поля ввода
(`setChatMenuButton`), а в `/help` появляется кнопка **🌐 Открыть панель**.

### Вход без пароля

Дашборд внутри Telegram не спросит токен: страница берёт `initData` из
`Telegram.WebApp`, отправляет в `POST /tg/auth`, ядро проверяет подпись
(HMAC-SHA256 на токене бота), сверяет пользователя со списком
`TELEGRAM_ALLOWED_CHAT_IDS` и возвращает токен ассистента.

Что проверяется на стороне ядра:

| Проверка | Результат при провале |
|---|---|
| подпись `hash` совпадает с HMAC на токене бота | 401 «подпись не совпадает» |
| `auth_date` не старше суток | 401 «данные устарели» |
| `TELEGRAM_ALLOWED_CHAT_IDS` задан | 401 «вход запрещён» (fail closed) |
| пользователь в списке разрешённых | 401 «не в списке разрешённых» |

> **Важно:** если `TELEGRAM_ALLOWED_CHAT_IDS` пуст, вход через панель закрыт
> полностью — так же, как и у бота. Список пуст → ничего не выполняется.

> Панель доступна только устройствам в вашем tailnet. Если нужен доступ из
> любой сети — есть `tailscale funnel`, но тогда дашборд станет публичным
> в интернете. Так делать не стоит, пока `/shots` (скриншоты) отдаётся без
> авторизации.

### Вход в браузере

Вне Telegram панель спрашивает **токен ассистента** (`ASSISTANT_TOKEN` из
`.env`). Он сохраняется в localStorage браузера — вводить нужно один раз.
Сессия браузера отдельная (`web-<id>`), поэтому переписка в веб-панели не
смешивается с перепиской бота; сменить сессию или стереть её можно в разделе
**Ещё** («Очистить историю», «Токен доступа»).

## Обслуживание

```bash
journalctl -u net-assistant-telegram -f      # логи
sudo systemctl restart net-assistant-telegram
```

Если бот молчит:

1. `systemctl is-active net-assistant-telegram` — процесс жив;
2. в логах `getUpdates` — есть ли доступ к `api.telegram.org` из ВМ;
3. `TELEGRAM_ALLOWED_CHAT_IDS` содержит ваш chat_id;
4. токен не занят другим процессом (Telegram отдаёт `409 Conflict`, если
   один токен опрашивают из двух мест).

## Безопасность

- Токен бота и общий `ASSISTANT_TOKEN` лежат в `.env` (не в git, режим `600`).
- Разрешённые чаты задаются явно; при пустом списке бот не выполняет команды.
- Всё, что бот делает, попадает в журнал ядра: `data/audit.jsonl`.
- Бот и ядро живут на одной машине и общаются по `127.0.0.1`, наружу
  трафик к устройствам не идёт.
- Если токен утёк — BotFather `/revoke` и новый токен в `.env`.
