# Планировщик ежедневных задач

Планировщик живёт **внутри ядра** (`core/scheduler.py`) и не требует внешнего
cron или systemd-таймера. Задачи умеют обращаться к агентам (роутер, ПК,
телефон), складывать результат в общую историю и отправлять его в Telegram.

## Что уже настроено

При первом запуске ядро создаёт задачу:

- **«Ежедневный отчёт по роутеру»** — каждый день в **10:00 Europe/Moscow**,
  вид `router_report`.

Отчёт включает:

- uptime, нагрузку, память, диски (система, SSD, tmpfs);
- WAN (IP, интерфейс), доступность интернета (ping), работу DNS;
- прокси tachyon/sing-box, таблицу nft, watchdog и fix-loop;
- Tailscale (адрес, раздача exit-node);
- количество DHCP-аренд и Wi-Fi-клиентов;
- разбор последних 400 строк `logread`: критичные ошибки, предупреждения и
  **человеческие пояснения** к известным сообщениям (DNS-rebind dnsmasq,
  IPv6-релей Tailscale, peerapi, телеметрия 429).

Если критичных ошибок нет, отчёт так и пишет: «Критичных проблем нет».
Известные предупреждения не считаются сбоем и объясняются в тексте.

## Управление из чата

Бот умеет создавать, смотреть и удалять задачи сам — через действия ядра:

| Действие | Что делает |
|---|---|
| `core::schedule.list` | показать задачи, время, дни и следующий запуск |
| `core::schedule.add` | создать или обновить задачу |
| `core::schedule.remove` | удалить по id или названию |
| `core::schedule.run` | выполнить сейчас (например, показать отчёт) |

Примеры просьб:

- «Присылай мне каждый день в 10:00 отчёт по роутеру. И проверяй его логи.»
- «Сделай отчёт по роутеру в 9:30 по будням.»
- «Какие задачи в расписании?»
- «Покажи отчёт по роутеру сейчас.»
- «Убери ежедневный отчёт.»

Модель сама вызывает `schedule.add` с `kind="router_report"`. Если задача с
таким же названием уже есть, она **обновляется**, а не дублируется.

Для произвольной задачи ИИ используйте `kind="prompt"`:

```text
Создавай каждый день в 08:00 задачу: проверь свободное место на SSD роутера
и напиши, если занято больше 90%.
```

Внутри это выглядит так:

```json
{"device": "core", "action": "schedule.add", "args": {
  "title": "Проверка SSD",
  "time": "08:00",
  "kind": "prompt",
  "prompt": "Проверь свободное место на SSD роутера и напиши, если занято больше 90%."
}}
```

## HTTP API

```bash
# список задач
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8787/schedules

# создать/обновить
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Ежедневный отчёт по роутеру","time":"10:00","kind":"router_report"}' \
  http://127.0.0.1:8787/schedules

# выполнить сейчас (deliver=true — ещё и отправить в Telegram)
curl -X POST -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8787/schedules/<id>/run?deliver=false"

# удалить
curl -X DELETE -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:8787/schedules/<id>
```

## Настройки в `.env`

```dotenv
SCHEDULE_ENABLED=true
SCHEDULE_TZ=Europe/Moscow
# пусто — первый chat_id из TELEGRAM_ALLOWED_CHAT_IDS
SCHEDULE_CHAT_ID=
# сколько минут после назначенного времени ещё можно выполнить задачу,
# если ядро было выключено (0 — не догонять)
SCHEDULE_CATCH_UP_MINUTES=120
```

## Где хранится

`data/schedules.json`:

```json
{
  "tasks": [
    {
      "id": "12c45b",
      "title": "Ежедневный отчёт по роутеру",
      "time": "10:00",
      "kind": "router_report",
      "prompt": "",
      "days": [],
      "enabled": true,
      "last_run": "2026-10-21",
      "last_status": "ok",
      "last_error": ""
    }
  ]
}
```

`days` — список `mon/tue/wed/thu/fri/sat/sun`; пусто — каждый день.
`last_run` хранится как дата, поэтому после перезапуска ядра задача не
выполнится повторно в тот же день.

## Как это работает

1. При старте ядро запускает фоновый цикл (`asyncio`), проверка раз в 15 секунд.
2. Если наступило время задачи и сегодня она ещё не выполнялась — она
   запускается.
3. `router_report` вызывает действие `router.report` у агента роутера
   (только чтение, подтверждение не требуется).
4. Результат форматируется по-русски, сохраняется в историю с
   `source="schedule"` и отправляется владельцу в Telegram.
5. Бот не пересылает это сообщение повторно: `sync_loop` пропускает
   `source="schedule"`.
6. Если ядро было выключено, задача выполнится при старте в пределах
   `SCHEDULE_CATCH_UP_MINUTES`. Позже — помечается `skipped` до следующего дня.
7. Если выполнить не удалось (роутер недоступен, ошибка SSH), в Telegram
   уходит предупреждение, а причина сохраняется в `last_error`.

## Диагностика

```bash
# состояние задач
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8787/schedules | python3 -m json.tool

# журнал планировщика
journalctl -u net-assistant-core -n 100 --no-pager | grep scheduler

# ручной запуск отчёта без Telegram
curl -X POST -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8787/schedules/<id>/run?deliver=false"
```

Если в отчёте появились **неизвестные** критичные ошибки, они показываются
отдельно с уровнем `[error]` и не скрываются. Известные шаблоны описаны в
`agents/router_agent.py` (`KNOWN_LOG_PATTERNS`).
