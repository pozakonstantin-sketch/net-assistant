# Телефон: пульт управления и агент (Android + Termux)

Телефон (у нас Honor FLC-AN00, без root) играет две роли:

1. **Пульт** — открываем дашборд ядра в браузере/как приложение и управляем
   всеми устройствами перепиской.
2. **Устройство** — в Termux живёт `android_agent`, который сам подключается к
   ядру по WebSocket и выполняет команды (приложения, батарея, SMS, Wi-Fi,
   фонарик, громкость, TTS, скриншот, нажатия и т.п.).

Наружу порты не открываются: и телефон, и ПК — просто клиенты Tailscale, а ядро
живёт в ВМ и доступно по своему tailnet-адресу.

```
Honor (браузер/PWA) ─┐
                     ├─ Tailscale ──> ВМ assistant-hub (ядро + OpenCode)
Honor (Termux-агент) ┘                       100.67.117.60:8787
```

---

## 0. Что понадобится

| Что | Откуда | Зачем |
|---|---|---|
| Tailscale | Play Store или [F-Droid](https://f-droid.org/packages/com.tailscale.ipn/) | доступ к ядру из любой сети |
| Termux | **только F-Droid** (версия в Play Store устарела) | среда для агента |
| Termux:API | F-Droid | мост к функциям Android (`termux-battery-status` и т.п.) |
| Termux:Boot | F-Droid (по желанию) | автозапуск агента после перезагрузки |

> Termux и Termux:API должны быть из одного источника (F-Droid). Пакеты
> Play Store и F-Droid несовместимы — `termux-*` команды просто не найдутся.

---

## 1. Tailscale на телефоне

1. Установите Tailscale, войдите **в тот же аккаунт**, что и на ПК/в ВМ.
2. Проверьте, что виден узел `assistant-hub` с адресом `100.67.117.60`.
3. Откройте в браузере `http://100.67.117.60:8787` — должен появиться экран
   ввода токена.

Если узла нет:

```bash
# в ВМ
tailscale status
sudo systemctl restart tailscaled   # помогает, если узел показан offline
```

---

## 2. Дашборд как приложение (PWA)

1. Откройте `http://100.67.117.60:8787`.
2. Введите **токен** (`ASSISTANT_TOKEN` из `.env` ВМ) — он сохранится в браузере.
3. Меню браузера → «Добавить на главный экран».

Дашборд адаптирован под телефон: одна колонка (диалог → команда → устройства →
подтверждения → журнал), крупные поля ввода, микрофон для голоса.

> Полноценная установка PWA (не просто ярлык) требует HTTPS. Браузер разрешает
> установку без HTTPS только для `localhost`. Если хотите настоящую установку —
> см. раздел 6 ниже (`tailscale serve`).

### Голосовой ввод

- **Проще всего:** кнопка микрофона на клавиатуре (Gboard) прямо в поле ввода
  дашборда — распознаёт сам Android, ничего настраивать не нужно.
- Кнопка 🎤 в дашборде вызывает `/voice` ядра; для неё нужен STT — облачный
  ключ (`STT_API_KEY`) либо локальный `faster-whisper` (в ВМ это ещё 4–6 ГБ
  памяти). Без настройки эндпоинт отвечает `503`, и это не ошибка установки.

## 3. Установка агента в Termux (одна команда)

Откройте Termux (из F-Droid) и выполните **одну** команду, подставив токен:

```bash
curl -fsSL "http://100.67.117.60:8787/android/install.sh?token=ВАШ_ТОКЕН" | bash
```

Важно: запрос должен идти **на tailnet-адрес ВМ** — ядро подставляет его в
сгенерированный скрипт, чтобы агент потом подключался именно туда. Если открыть
установщик через `127.0.0.1`, в скрипт попадёт `127.0.0.1` и агент не найдёт ядро.

Что делает скрипт:

1. `pkg install python termux-api curl tar`
2. скачивает `android/bundle.tar.gz` (агент + минимальные модули ядра) в
   `~/net-assistant`;
3. пишет `~/net-assistant/.env`:
   ```ini
   CORE_URL=ws://100.67.117.60:8787
   ASSISTANT_TOKEN=...
   ANDROID_DEVICE_ID=phone
   ANDROID_DEVICE_NAME=Honor
   ```
4. ставит `websockets` и `python-dotenv`;
5. кладёт автозапуск в `~/.termux/boot/start-agent.sh`;
6. берёт `termux-wake-lock` и запускает агента: `python -m agents.android_agent`
   (лог — `~/agent.log`).

Проверка:

```bash
tail -f ~/agent.log        # должно быть "подключено к ядру" / список действий
pgrep -f agents.android_agent
```

В дашборде появится устройство **phone (Honor)**.

## 4. Разрешения Android (важный шаг)

Без этих пунктов часть команд будет молча падать.

1. **Termux:API**: при первом вызове (`termux-battery-status`, `termux-sms-list`,
   `termux-location`) система покажет запросы — разрешите SMS, уведомления,
   местоположение, камеру.
2. Настройки → Приложения → **Termux** → Батарея → **Без ограничений**
   (иначе система усыпит агент и он отвалится от ядра).
3. Termux → настройки уведомлений: включить, чтобы wakelock работал стабильно.
4. Если установлен Termux:Boot — один раз откройте его после установки, чтобы
   система зарегистрировала автозапуск.

## 5. Что умеет телефонный агент

| Действие | Что делает |
|---|---|
| `sys.info` | модель, версия Android, заряд |
| `battery.status` | заряд, температура, режим |
| `net.status`, `wifi.info` | сеть, Wi-Fi, IP |
| `apps.list` | список приложений (`third_party=true` — только пользовательские) |
| `app.info`, `app.current` | сведения о приложении / что сейчас на экране |
| `app.open` | запуск приложения (пакет, например `org.telegram.messenger`) |
| `app.stop` ⚠ | принудительная остановка приложения |
| `screen.shot` | скриншот экрана |
| `ui.dump` | дерево элементов интерфейса |
| `screen.tap`, `screen.swipe`, `screen.text`, `screen.key` | нажатия, свайпы, ввод текста, кнопки |
| `notify.send`, `tts.speak` | уведомление, озвучка |
| `sms.list`, `sms.send` ⚠ | чтение и отправка SMS |
| `torch.set` | фонарик |
| `fs.list`, `fs.read`, `shell.run` ⚠ | файлы и ограниченная оболочка |
| `exec.run`, `fs.write`, `fs.delete`, `proc.kill` ⚠ | полный доступ: включается `ACCESS_MODE=full` |

⚠ — действия, требующие подтверждения токеном (`REQUIRE_CONFIRM=true`).

`app.open` определяет launcher-активность через `cmd package resolve-activity`;
если система это запрещает — откатывается на `monkey`.

## 6. По желанию: HTTPS через `tailscale serve`

Даёт красивый адрес `https://assistant-hub.<ваш-tailnet>.ts.net`, настоящую
установку PWA и шифрование. В ВМ:

```bash
sudo tailscale serve --bg 8787          # https://assistant-hub.<tailnet>.ts.net -> localhost:8787
tailscale serve status
# сертификат (если нужен файл):
sudo tailscale cert assistant-hub.<tailnet>.ts.net
```

После этого открывайте дашборд по HTTPS-адресу, а установщик агента запускайте
как `curl -fsSL "https://<адрес>/android/install.sh?token=..." | bash` — ядро само
подставит `wss://` для агента.

## 7. Диагностика

| Симптом | Что проверить |
|---|---|
| Устройства `phone` нет в дашборде | `pgrep -f agents.android_agent`, `tail -30 ~/agent.log`, `tailscale status` на телефоне |
| Агент отключается через минуты | отключить оптимизацию батареи для Termux, включить `termux-wake-lock` (скрипт это делает) |
| `termux-*: command not found` | установлен Termux:API? Termux и Termux:API из F-Droid? |
| `sms.*` не работает | разрешение SMS не выдано Termux:API |
| `app.open` не запускает | приложение не установлено, либо система блокирует `cmd`; попробуйте `app.info` для проверки пакета |
| Дашборд не открывается | телефон в том же tailnet? `tailscale status` в ВМ показывает узел online? |
| Узел ВМ `offline` | в ВМ работает сторож `tailscale-watchdog.timer` (сам перезапускает `tailscaled`); проверить: `tail -f /var/log/tailscale-watchdog.log`. Вручную — `sudo systemctl restart tailscaled` |

Повторная установка/обновление агента — просто выполните ту же команду из
раздела 3: она перезапишет файлы, `.env` и перезапустит процесс.

---

## 8. Безопасность

- Токен из ссылки установщика попадает в историю Termux — это ваш общий секрет;
  не пересылайте ссылку, а после установки при желании очистите историю:
  `history -c`.
- Ядро слушает `0.0.0.0:8787`, но добраться до него можно только из локалки и
  из tailnet. Наружу порт не публикуется.
- Режим доступа задаётся `ACCESS_MODE` в `.env` телефона: `restricted` (белые
  списки) или `full` (произвольные команды Termux, запись/удаление файлов).
- Опасные действия (SMS, `app.stop`, `shell.run`, перезагрузка роутера…)
  выполняются только после подтверждения токеном. Отключение — `REQUIRE_CONFIRM=false`,
  но так делать не советуем.
