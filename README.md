# Net Assistant

Домашний ассистент, который управляет ПК, смартфоном и роутером: вы пишете
фразу в чат, LLM выбирает команду, агент на устройстве её выполняет.

Ключевая идея — **агенты сами подключаются к ядру** (исходящее соединение).
На устройствах не нужно открывать порты, а наружу ничего не торчит.

```
        ┌──────────────────────┐
Вы ───► │  ЯДРО (core)         │  FastAPI + WebSocket
        │  LLM + каталог + аудит│
        └──────────┬───────────┘
                   │  исходящие WS-соединения
     ┌─────────────┼──────────────┬─────────────┐
 агент ПК      агент Android   агент роутера   fake-агенты (лаборатория)
 Windows       Termux + API    SSH (OpenWrt…)
```

## Возможности

| Устройство | Команды |
|---|---|
| **ПК (Windows)** | снимок экрана, список процессов, сведения о системе, диагностика сети, громкость, блокировка экрана, файлы, `shell.run`; в режиме `full` — произвольный PowerShell, запись/удаление файлов, завершение процессов, питание |
| **Android (без root)** | заряд, SMS (чтение/отправка), уведомления, озвучка, фонарик, WiFi, геолокация, запуск/остановка приложений, список приложений и сведения о них; в режиме `full` — произвольные команды Termux и файлы. **Экран телефона** (снимок, разбор интерфейса, нажатия, свайпы, ввод текста, кнопки) — через adb отдельным агентом, который работает в ВМ |
| **Роутер** | статус, список клиентов, вкл/выкл WiFi, отключение клиента по MAC, перезагрузка; в режиме `full` — произвольные команды по SSH и файлы |
| **Рабочий стол ВМ (Astra)** | снимок экрана, список окон, открытие ссылки/файла, наведение, клик, прокрутка, ввод текста, клавиши и сочетания. Так ИИ сам открывает панель в браузере ВМ, нажимает кнопки и проверяет результат |
| **Лаборатория** | `fake_agent.py` — виртуальные устройства, включая опасные команды, без риска |

Пульт — **веб-панель** (`http://<ядро>:8787`) и **мини-приложение Telegram**.
В браузере открывается десктопный интерфейс (сайдбар с устройствами, широкий
чат), в Telegram — мобильный в стиле Android. Переписка с ИИ хранится на ядре
и не теряется после перезагрузки. Есть **голосовой ввод** (микрофон → Whisper →
команда → ответ голосом).

## ИИ-планировщик: бесплатные модели OpenCode

По умолчанию ядро планирует действия **бесплатными моделями OpenCode**
(`opencode/deepseek-v4.1-flash-free`) — без ключей и подписок. Модель живёт
«внутри» OpenCode, поэтому ядро запускает CLI `opencode run` на той же машине:

```
ядро ──> opencode run ──> JSON-план {"reply": "...", "actions": [...]}
   │                          │
   ├─ проверка по каталогу команд
   ├─ опасные действия → токен подтверждения
   └─ выполнение агентами → результат снова модели → ответ пользователю
```

- режим задаётся `LLM_BACKEND` (`auto` / `opencode` / `openai`); при пустом
  `LLM_API_KEY` и установленном CLI `auto` выбирает бесплатные модели;
- если вписать `LLM_API_KEY`, тот же код работает с любым OpenAI-совместимым
  провайдером (DeepSeek, OpenRouter, Groq…) — без изменений в логике;
- проверить режим: `curl -s localhost:8787/health` → `"llm_backend"`.

Подробности, грабли и диагностика — `docs/OPENCODE_PLANNER.md`.

## Телефон (Honor) как пульт и как устройство

- **Пульт:** тот же дашборд по tailnet-адресу ядра, ставится на главный экран
  как PWA (одна колонка, крупные элементы, микрофон).
- **Устройство:** в Termux (F-Droid) — `android_agent`, ставится одной командой:

  ```bash
  curl -fsSL "http://<tailnet-ip-ядра>:8787/android/install.sh?token=<ТОКЕН>" | bash
  ```

  Скрипт сам подставляет адрес ядра, токен, ставит зависимости, `termux-wake-lock`
  и автозапуск через Termux:Boot.

- **Экран:** Android не разрешает приложению нажимать за пользователя, поэтому
  экран ведёт отдельный агент **в ВМ** — `agents/phone_screen_agent.py` — через
  `adb` по сети (TCP 5555). ПК в этом не участвует. Действия: `screen.ui`,
  `screen.shot`, `screen.tap`, `screen.swipe`, `screen.text` (кириллица через
  ADBKeyboard, `clear=true` очищает поле), `screen.key`, `app.open` (пакет или
  русское название — «Часы», «Настройки»). Телефон ищется и по mDNS, если IP
  сменился. Настройка и ограничения — `docs/PHONE_SETUP.md`.

Полная инструкция — `docs/PHONE_SETUP.md`.

### Рабочий стол ВМ: ИИ видит экран и работает с панелью

Внутри ВМ работает ещё один агент — `agents/vm_agent.py` (X11, `DISPLAY=:0`).
Он даёт ассистенту «глаза и руки» на рабочем столе Astra:

- `vm.screenshot` — снимок экрана (модель видит, что открыто);
- `vm.windows` — видимые окна и координаты;
- `vm.open` — открыть ссылку или файл (например, панель в браузере);
- `vm.click`, `vm.move`, `vm.scroll` — мышь;
- `vm.type` — ввод текста (кириллица через буфер обмена + Ctrl+V);
- `vm.key` — клавиши и сочетания (`Return`, `ctrl+l`, `F5`, …).

Чтобы сессия всегда была на месте, включён автологин пользователя `assistant`
в fly-dm. Установка и запуск:

```bash
sudo /opt/net-assistant/deploy/setup_vm_desktop.sh
```

Скрипт ставит `python-xlib`, включает автологин и запускает
`net-assistant-vm-desktop.service`. Панель можно открыть сразу с токеном:
`https://<адрес-ядра>/?token=<ТОКЕН>` — ссылка запоминается в браузере.

## Быстрый старт (Windows, локально)

```powershell
cd net-assistant
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt

copy .env.example .env      # и вписать ASSISTANT_TOKEN, LLM_API_KEY
```

Токен можно сгенерировать так:

```powershell
.\.venv\Scripts\python -c "import secrets;print(secrets.token_urlsafe(32))"
```

Запуск ядра (терминал 1):

```powershell
.\.venv\Scripts\python -m core.main
```

Агент ПК (терминал 2) и тестовые устройства (терминалы 3–5):

```powershell
.\.venv\Scripts\python -m agents.pc_agent

$env:FAKE_KIND='pc';     .\.venv\Scripts\python -m agents.fake_agent
$env:FAKE_KIND='router'; .\.venv\Scripts\python -m agents.fake_agent
$env:FAKE_KIND='android';.\.venv\Scripts\python -m agents.fake_agent
```

Проверка:

```powershell
.\tools\smoke_test.ps1
```

Дашборд: откройте **http://127.0.0.1:8787**, вставьте токен из `.env` — увидите
устройства, чат, подтверждения, журнал и кнопку микрофона.

## Telegram-бот

Управлять ассистентом можно из Telegram — бот живёт в ВМ рядом с ядром,
работает через long polling (входящие порты не нужны) и умеет текстом,
голосом, кнопками подтверждения и скриншотами:

```
Telegram → api.telegram.org → ВМ: core.telegram_bot → ядро → ПК / телефон / роутер
```

```bash
# 1. @BotFather → /newbot → токен
# 2. в .env на ВМ:
TELEGRAM_BOT_TOKEN=123456789:AAE...
TELEGRAM_ALLOWED_CHAT_IDS=          # пусто → бот не выполняет команды, только подскажет chat_id
# 3. запуск
sudo systemctl enable --now net-assistant-telegram
```

Подробно: [`docs/TELEGRAM.md`](docs/TELEGRAM.md).

Автозапуск агента ПК при входе (чтобы не держать терминал):

```powershell
.\tools\install_pc_agent.ps1 -RunNow              # обычные права
.\tools\install_pc_agent.ps1 -Elevated -RunNow    # с правами администратора
# удалить: -Remove
```

> `-Elevated` регистрирует задачу с `RunLevel Highest`: ИИ сможет управлять службами,
> ставить программы и менять системные настройки. Регистрация задачи требует UAC.
> Без `-Elevated` агент работает с обычными правами пользователя.

> Для первого запуска используйте **fake-агентов**, а не реальный ПК — см.
> `docs/VM_SETUP.md`. Реальный агент включайте только когда сценарии отлажены.

## API

Все запросы требуют заголовок `Authorization: Bearer <ASSISTANT_TOKEN>`.

```powershell
$h = @{ Authorization = "Bearer $env:TOKEN" }

# диалог с LLM
Invoke-RestMethod http://127.0.0.1:8787/chat -Method Post -Headers $h `
  -ContentType 'application/json' -Body '{"message":"сделай скриншот и покажи, что на экране"}'

# прямой вызов команды (без LLM)
Invoke-RestMethod http://127.0.0.1:8787/cmd -Method Post -Headers $h `
  -ContentType 'application/json' -Body '{"device":"pc-desktop","action":"proc.list","args":{"limit":5}}'

# подтверждение опасного действия
Invoke-RestMethod http://127.0.0.1:8787/confirm/ab12cd -Method Post -Headers $h

# что подключено / что произошло
Invoke-RestMethod http://127.0.0.1:8787/devices -Headers $h
Invoke-RestMethod http://127.0.0.1:8787/audit?limit=20 -Headers $h

# единая сессия для всех устройств (бот, мини-апп, браузер)
Invoke-RestMethod http://127.0.0.1:8787/session -Headers $h

# сохранённая переписка (по умолчанию tg-<id владельца>)
Invoke-RestMethod "http://127.0.0.1:8787/history?session=tg-123456789&limit=50" -Headers $h
Invoke-RestMethod http://127.0.0.1:8787/sessions -Headers $h

# распознать скриншот и ответить в диалоге
curl.exe -X POST -H "Authorization: Bearer $env:TOKEN" -F "file=@screen.png" `
  "http://127.0.0.1:8787/image?chat=true&session=tg-123456789&message=что%20тут%3F"

# очистить контекст и историю сессии
Invoke-RestMethod http://127.0.0.1:8787/session/tg-123456789 -Method Delete -Headers $h

# состояние ядра и активный планировщик (доступно без токена)
Invoke-RestMethod http://127.0.0.1:8787/health

# установка агента на телефон: готовый скрипт для Termux (токен в query)
curl.exe -fsSL "http://<адрес-ядра>:8787/android/install.sh?token=$env:TOKEN" -o install.sh
# и архив с кодом агента (его скачивает сам скрипт)
curl.exe -fsSL "http://<адрес-ядра>:8787/android/bundle.tar.gz?token=$env:TOKEN" -o bundle.tar.gz

# голос: распознать и сразу выполнить (multipart, поле file)
curl -H "Authorization: Bearer $env:TOKEN" -F "file=@voice.webm" `
  "http://127.0.0.1:8787/voice?chat=true"
```

В чате опасное действие сначала возвращает токен, а выполняется после
`подтверждаю <токен>` (или `POST /confirm/<токен>`). Отмена — слово `отмена`.

## Безопасность

1. **Каталог команд** (`core/catalog.py`) — единственный источник правды.
   LLM не может придумать команду: неизвестное действие ядро отклонит.
2. **Строгая проверка аргументов** по схемам, без `eval` и произвольного кода.
3. **Опасные действия** (`dangerous=True`) не выполняются без подтверждения.
4. **Два режима доступа** (`ACCESS_MODE` в `.env`):
   - `restricted` (по умолчанию) — белые списки: `shell.run` только диагностические
     программы, `fs.*` только разрешённые каталоги, цепочки `&&`/`|`/`>` запрещены;
   - `full` — произвольные команды PowerShell/cmd/sh на ПК, в Termux и на роутере,
     запись/удаление файлов, управление процессами и питанием. Права равны правам
     пользователя, под которым запущен агент (агент ПК можно поставить с `-Elevated`).
5. **Один общий токен** на ядро и агентов, журнал в `data/audit.jsonl`,
   TTL у каждой команды (устаревшая не выполнится).

> **Важно.** В режиме `full` команда `shell.run` может сделать что угодно — это и есть
> «полный доступ». Подтверждение (`REQUIRE_CONFIRM=true`) по-прежнему запрашивается для
> явно опасных действий: `exec.run`, `fs.write`, `fs.delete`, `proc.kill`, `power.action`,
> `router.wifi`, `router.kick`, `router.reboot`, `sms.send` и т. п. Если нужна полностью
> автономная работа без кликов — поставьте `REQUIRE_CONFIRM=false` (на свой риск).

Токен — общий секрет: при компрометации смените `ASSISTANT_TOKEN` и перезапустите
агентов. Для домашней сети этого достаточно; для интернета используйте Tailscale
(см. `docs/VM_SETUP.md`) и, при желании, оформите агентов как отдельные ключи.

## Как добавить свою команду

1. В `core/catalog.py` описать действие: `desc`, `args` (схема), `devices`,
   при необходимости `dangerous: True`.
2. В нужном агенте добавить обработчик в `HANDLERS` (чистая функция `args -> dict`).
3. Перезапустить агента и ядро. Больше нигде править не нужно: LLM увидит
   инструмент сам, а валидация аргументов уже включена.

## Панель

Один адрес — `http://<ядро>:8787/` — и два интерфейса:

- **в Telegram** (мини-приложение) — мобильный: верхняя строка, нижняя
  навигация, чат пузырями, шторки и диалоги, безопасные отступы. Вход без
  пароля по `initData`; сессия `tg-<user_id>` — та же переписка, что и у бота.
- **в браузере** — десктопный: слева сайдбар (чат, устройства, журнал, «Ещё»,
  список устройств с индикаторами), справа широкий чат; на узком окне
  автоматически включается мобильная раскладка. Вход по токену (хранится в
  localStorage), сессия `web-<id>` — своя.

Экраны: **Чат** (ответы, выполненные команды, скриншоты), **Устройства**
(прямой вызов команды), **Журнал** (подтверждения + аудит), **Ещё** (выбор
модели ИИ, очистка истории, смена токена, озвучка).

Переписка сохраняется на ядре в `data/history/<session>.jsonl` и подгружается
при открытии через `GET /history` — диалог не теряется после перезагрузки
страницы. Файл ограничен 400 сообщениями и 512 КБ: старые записи вытесняются,
а контекст для модели собирается из тех же данных (последние 24 реплики).

## Голос

### Ответы голосом (TTS)

Бот и панель озвучивают ответы мужским голосом `ru-RU-DmitryNeural`
(нейроголос Microsoft, `edge-tts`; ключи и регистрация не нужны). Синтез
идёт на ВМ, в OGG/Opus через `ffmpeg`, поэтому Telegram присылает обычное
голосовое сообщение.

| Переменная | Значение |
|---|---|
| `TTS_ENGINE` | `edge` (по умолчанию) или `off` |
| `TTS_VOICE` | `ru-RU-DmitryNeural` (мужской), `ru-RU-SvetlanaNeural` (женский) |
| `TTS_RATE` | темп, например `-4%` |
| `TTS_MAX_CHARS` | максимум символов на одну озвучку (900) |

В боте — `/voice on|off` (по умолчанию включено), в панели — переключатель
«Озвучивать ответы» в разделе **Ещё**. Эндпоинт ядра — `POST /tts`
(`{"text": "..."}` → `audio/ogg`), кэш — `data/tts`.

`ffmpeg` ставится скриптом `deploy/install_ffmpeg.sh` (статическая сборка).

### Распознавание речи (STT)

По умолчанию работает **локально**: `faster-whisper` с моделью `small`
(~500 МБ, скачивается при первом запуске, ~2 с на голосовое сообщение при
4 vCPU). Аудио никуда не уходит. Модель грузится в память при первом
голосовом сообщении (~2–4 с) и остаётся там.

`STT_ENGINE` в `.env`:

| Режим | Что нужно | Плюсы/минусы |
|---|---|---|
| `local` | `pip install faster-whisper` | приватно и бесплатно; модель ~500 МБ |
| `openai` | `STT_API_KEY` (или `LLM_API_KEY`) | быстро, ничего не грузит локально; аудио уходит в облако |
| `auto` | — | облако при наличии ключа, иначе локально |

Размер модели — `STT_LOCAL_MODEL` (`tiny|base|small|medium|large-v3`), язык —
`STT_LANGUAGE=ru`. На телефоне голосовые ответы дополнительно умеет
`tts.speak` через Termux.

## Автозапуск агента ПК

```powershell
.\tools\install_pc_agent.ps1 -RunNow              # обычные права
.\tools\install_pc_agent.ps1 -Elevated -RunNow    # с правами администратора
.\tools\install_pc_agent.ps1 -Remove
```

Это **задача планировщика при входе**, а не служба Windows. Причина
техническая: служба работает в сессии 0 и не видит рабочий стол, поэтому
скриншоты, громкость, буфер обмена и блокировка экрана были бы недоступны.
Задача запускается в вашей сессии.

В обычном режиме (`ACCESS_MODE=restricted`) безопасность обеспечивают белые
списки (`PC_SHELL_ALLOW`, `PC_FS_ROOTS`) и каталог команд ядра. В режиме
`ACCESS_MODE=full` белые списки сняты, а `-Elevated` даёт агенту права
администратора — это фактически полный контроль над ПК.

Запуск от отдельного пользователя возможен (`-User` + `-Password`), но тогда
агент окажется в другой сессии и потеряет доступ к рабочему столу — это вариант
для «headless» задач, не для скриншотов.

Лог: `data/agent-pc-desktop.log`.

### Включение, выключение и автозапуск ВМ

```powershell
cd C:\lab\net-assistant
.\tools\vm.ps1 status          # состояние, адрес, автозапуск (без UAC)
.\tools\vm.ps1 start           # включить (UAC)
.\tools\vm.ps1 stop            # корректно выключить: shutdown по SSH, затем Stop-VM
.\tools\vm.ps1 off             # жёстко выключить (как выдернуть питание)
.\tools\vm.ps1 restart         # перезагрузить
.\tools\vm.ps1 autostart on    # ВМ стартует вместе с ПК (+30 с)
.\tools\vm.ps1 autostart off   # только вручную
```

Скрипт сам запрашивает UAC — запускать из обычной сессии. Если PowerShell
ругается на политику выполнения:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\vm.ps1 status
```

Что происходит при выключении: сначала гость получает `poweroff` по SSH (это
безопасно, данные не теряются), и только если он не выключился за минуту —
`Stop-VM -Save`. Вариант `off` — это `Stop-VM -TurnOff`, без сохранения
состояния; используйте его, только если ВМ зависла.

Автозапуск (`autostart on`) означает: при загрузке Windows служба Hyper-V
сама поднимет ВМ через 30 секунд. Ядро и fake-агенты внутри ВМ стартуют
автоматически (systemd), поэтому после включения ПК достаточно подождать
~1 минуту. Сторож Tailscale (`tailscale-watchdog.timer`) тоже включён и
работает без участия человека.
