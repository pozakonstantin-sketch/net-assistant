# Присланные файлы: Word, Excel, PDF и другие

Пользователь присылает файл боту в Telegram или в панели — ядро в ВМ:

1. сохраняет **оригинал на SSD роутера** по SFTP;
2. оставляет локальный кэш и извлекает текст для планировщика;
3. отдаёт содержимое ИИ и возвращает ответ в ту же переписку.

Одна и та же переписка у бота, мини-приложения и браузера, поэтому файл,
присланный с телефона, виден и в веб-панели.

## Где лежат файлы

| Что | Где |
|---|---|
| Оригиналы и `.txt` с текстом | `/mnt/sda/net-assistant/files/<ГГГГ-ММ-ДД>/` на роутере |
| Локальный кэш | `/opt/net-assistant/data/files/` в ВМ |
| Индекс (id, имя, тип, размер, путь) | `data/files/index.jsonl` |

Диск `/mnt/sda` — SSD 233 ГБ на роутере OpenWrt. Каталог задаётся
переменной `ROUTER_FILES_DIR`.

Посмотреть на роутере:

```sh
ssh root@192.168.1.1
ls -lh /mnt/sda/net-assistant/files/$(date +%F)/
```

Если роутер недоступен, файл всё равно сохраняется локально на ВМ, а бот
честно пишет: «Сохранено только на ВМ: SSD роутера недоступен».

## Поддерживаемые форматы

| Формат | Как разбирается |
|---|---|
| `.docx` | python-docx: абзацы и таблицы |
| `.xlsx` | openpyxl: все листы, строки через табуляцию |
| `.pdf` | `pdftotext -layout`, запасной вариант — pypdf |
| `.doc` | `catdoc`, запасной — `antiword` |
| `.xls` | `xls2csv` |
| `.ppt` / `.pptx` | `catppt` / XML презентации |
| `.rtf` | `unrtf` |
| `.odt/.ods/.odp` | XML внутри OpenDocument |
| `.txt .csv .md .json .xml .html .log .py .sh …` | как текст, с определением кодировки |
| `.zip` | список файлов с размерами |
| картинки | присылайте как фото — их читает модель зрения (`/image`) |

Файлы больше `FILES_MAX_MB` (по умолчанию 50 МБ) не принимаются.
Telegram отдаёт ботам файлы до 20 МБ — большие загружайте через панель.

## Что делает ИИ

После загрузки текст файла уходит планировщику как реплика пользователя:
ассистент пересказывает документ, находит нужные строки, считает итоги по
таблице, отвечает на вопросы. Подпись к файлу в Telegram (`caption`)
становится вопросом: «Сделай выжимку» и т. п.

Для последующих вопросов у ИИ есть локальные действия ядра:

- `core::file.list` — список присланных файлов (id, имя, тип, размер, путь);
- `core::file.read(id, offset, limit)` — прочитать извлечённый текст;
- `core::file.search(query)` — найти строку во всех файлах.

Они не опасные и не требуют подтверждения.

## Ручная проверка

```sh
TOKEN=<ASSISTANT_TOKEN>
# без вызова ИИ: только сохранить и извлечь текст
curl -s -H "Authorization: Bearer $TOKEN" \
  -F "file=@otchet.docx" \
  "http://127.0.0.1:8787/file?chat=false"

# с ответом ИИ (текст попадает в общую переписку)
curl -s -H "Authorization: Bearer $TOKEN" \
  -F "file=@otchet.docx" \
  "http://127.0.0.1:8787/file?chat=true&session=tg-270709065&message=Сделай выжимку"
```

`/health` показывает сводку: количество файлов, каталог на роутере,
доступность хранилища.

## Если что-то не так

- **«SSD роутера недоступен»** — проверьте `ROUTER_HOST`, `ROUTER_USER`,
  `ROUTER_PASSWORD` в `.env` и что диск смонтирован: `df -h | grep sda`.
- **«Текст извлечь не удалось»** — формат бинарный или повреждён; оригинал
  всё равно сохранён, можно скачать и открыть вручную.
- **Скан PDF без текста** — распознавания OCR пока нет; пришлите страницы
  как фото, их прочитает модель зрения.
- После изменения `.env` перезапустите ядро и бота:
  `sudo systemctl restart net-assistant-core net-assistant-telegram`.
