# Telegram-бот

Пульт к ядру ассистента прямо в Telegram: пишете боту текстом или голосом —
он управляет ПК, телефоном и роутером. Работает **через long polling**, поэтому
входящие порты открывать не нужно: ВМ сама ходит на `api.telegram.org`.

## Схема

```
Telegram  ──►  api.telegram.org  ──►  ВМ: core.telegram_bot  ──►  ядро (/chat)
                                             │                      │
                                        кнопки «Подтвердить»    ПК / телефон / роутер
```

Бот не содержит логики управления: он только пересылает текст в `/chat` ядра,
показывает кнопки подтверждения опасных действий и присылает скриншоты.

## Установка

1. **Создать бота.** В Telegram напишите [@BotFather](https://t.me/BotFather):
   ```
   /newbot
   ```
   Придумайте имя и username (должен заканчиваться на `bot`). BotFather пришлёт
   токен вида `123456789:AAE...`.

2. **Вписать токен в `.env` на ВМ:**
   ```bash
   sudo nano /opt/net-assistant/.env
   # TELEGRAM_BOT_TOKEN=123456789:AAE...
   ```

3. **Запустить бота:**
   ```bash
   sudo systemctl enable --now net-assistant-telegram
   sudo systemctl status net-assistant-telegram
   ```

4. **Узнать свой chat_id.** Напишите боту любое сообщение — он ответит:
   > ℹ️ Ваш chat_id: `123456789`

5. **Закрыть доступ** — впишите id в `.env` и перезапустите:
   ```bash
   # TELEGRAM_ALLOWED_CHAT_IDS=123456789
   sudo systemctl restart net-assistant-telegram
   ```
   > Пока список пуст, бот **не выполняет** команды ни от кого: он только
   > подсказывает chat_id. Так чужой человек не получит доступ к вашему ПК.

## Как пользоваться

Просто пишите задачу обычными словами:

| Сообщение | Что произойдёт |
|---|---|
| Какая температура телефона? | `battery.status` на телефоне |
| Сделай скриншот ПК | `sys.screenshot`, бот пришлёт картинку |
| Кто подключён к роутеру? | `router.clients` |
| Выключи WiFi на роутере | запросит подтверждение кнопкой |
| Поставь громкость 30% | `media.volume` на ПК |

Голосовое сообщение распознаётся (если настроен STT — `STT_ENGINE`) и
выполняется как обычная реплика.

### Команды

| Команда | Действие |
|---|---|
| `/status` | ядро, модель ИИ, список устройств |
| `/pending` | что ждёт подтверждения (с кнопками) |
| `/panel` | открыть панель (мини-приложение) |
| `/reset` | очистить контекст и историю диалога |
| `/help` | справка |

### Подтверждения

Опасные действия (`exec.run`, `fs.write`, `fs.delete`, `power.action`,
перезагрузка роутера, отправка SMS…) не выполняются сразу. Бот присылает
кнопки **✅ Подтвердить** / **❌ Отмена**, либо можно написать
`подтверждаю <токен>`.

Токен живёт 10 минут.

## Панель: Telegram и браузер

Панель — один веб-интерфейс с двумя раскладками:

- **мини-приложение Telegram** — мобильный интерфейс: верхняя строка, нижняя
  навигация, чат пузырями, шторки и диалоги. Вход без пароля по `initData`;
- **браузер** — десктопный интерфейс: слева сайдбар (навигация, статус, список
  устройств с индикаторами), справа широкий чат; на узком окне включается
  мобильная раскладка. Вход по токену ассистента.

Экраны одинаковые: **Чат**, **Устройства** (прямая команда), **Журнал**
(подтверждения + аудит), **Ещё** (выбор модели ИИ, очистка истории, смена
токена, озвучка).

### Одна переписка на всех устройствах

Бот, мини-приложение и веб-панель работают с **одной сессией** — её отдаёт
`GET /session` (по умолчанию `tg-<chat_id владельца>`, переопределяется
`CHAT_SESSION`). Поэтому:

- история и контекст ИИ общие: сказанное в браузере помнит бот и наоборот;
- панель каждые 4 секунды подтягивает `GET /history` — новые реплики с другого
  устройства появляются без перезагрузки;
- бот раз в 4 секунды смотрит ту же историю и пересылает в Telegram реплики,
  написанные с других устройств (`source != tg`), с пометкой
  «🌐 С другого устройства». Свои сообщения не дублируются.

Переписка хранится на ядре — `data/history/<session>.jsonl` — и подгружается
при открытии через `GET /history`, поэтому перезагрузка страницы или перезапуск
ядра её не теряют. Очистка — кнопкой «Очистить историю» в панели или
`DELETE /session/<session>` (в боте — `/reset`).

### Скриншоты и фото

Бот принимает фото и скриншоты: скачивает файл, прогоняет через бесплатную
модель со зрением (`VISION_MODEL`, по умолчанию
`opencode/nemotron-3.5-super-vl-free`) и добавляет распознанный текст в диалог.
Подпись к фото становится вопросом пользователя. Ответ приходит как обычная
реплика ИИ — с учётом того, что видно на картинке.

Эндпоинт ядра — `POST /image` (multipart: `file`, query: `message`, `session`,
`chat`, `source`).

Telegram требует **HTTPS** для мини-приложения. Дома это решает локальный
HTTPS на ВМ, вне дома — Tailscale Serve (в tailnet) или исходящий туннель.

### Панель по HTTPS в домашней сети (без VPN и туннелей)

Основной способ. Caddy на ВМ слушает LAN-адрес (`192.168.1.161:443`) с
сертификатом Let's Encrypt, который `tailscale cert` выдаёт для tailnet-имени
(`astra-hub.taile4385b.ts.net`), и проксирует запросы на `127.0.0.1:8787`.
На роутере (OpenWrt/dnsmasq) добавлена запись «имя → LAN-адрес ВМ».

Итог: телефон в домашней Wi-Fi открывает `https://astra-hub.taile4385b.ts.net`
**без Tailscale**, сертификат настоящий, поэтому Telegram не ругается.
Снаружи тот же адрес работает при включённом Tailscale (Serve).

```bash
# одной командой: Caddy, сертификат, systemd, DNS на роутере
sudo /opt/net-assistant/deploy/setup_lan_tls.sh

# проверить с любого устройства в домашней сети
curl --resolve astra-hub.taile4385b.ts.net:443:192.168.1.161 \
     https://astra-hub.taile4385b.ts.net/health
```

Сертификат продлевает `net-assistant-cert.timer` (раз в сутки, с перезагрузкой
Caddy). Проверка: `systemctl list-timers net-assistant-cert.timer`.

Файлы: `deploy/Caddyfile`, `deploy/net-assistant-tls.service`,
`deploy/net-assistant-cert.{sh,service,timer}`, `deploy/router_dns_panel.py`.

> На Android включённый «Частный DNS» (Private DNS) с конкретным именем
> сервера обходит DNS роутера — имя перестанет разрешаться в домашней сети.
> Нужно «Авто» или «Выкл».


### Туннель localhost.run (без аккаунта)

Сервис `tunnel-lhr.service` держит SSH-туннель до `localhost.run` и пишет
текущий адрес в `data/tunnel_url.txt`. Бот читает этот файл и ставит кнопку
**«Панель»**; если туннель переподключился и адрес сменился, кнопка
обновляется сама в течение 15 секунд.

```bash
# из каталога репозитория на ВМ
sudo install -m 755 deploy/tunnel-lhr.sh /usr/local/bin/tunnel-lhr.sh
sudo install -m 644 deploy/tunnel-lhr.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tunnel-lhr.service

cat /opt/net-assistant/data/tunnel_url.txt      # текущий адрес
curl -sS "$(cat /opt/net-assistant/data/tunnel_url.txt)/health"
```

Адрес вида `https://xxxxxxxxxxxx.lhr.life` меняется при каждом переподключении
(бесплатный тариф без аккаунта). Для мини-приложения это не проблема: бот
обновляет кнопку, а уже отправленные сообщения сохраняют старую ссылку.

### Cloudflare quick tunnel (альтернатива)

`deploy/cloudflared-quick.service` — туннель Cloudflare без аккаунта
(`https://<слова>.trycloudflare.com`). Адрес бот берёт из лога
`data/cloudflared.log`, но при авариях Cloudflare edge отдаёт 530/1033.
Переключение:

```bash
sudo systemctl disable --now tunnel-lhr.service
sudo systemctl enable --now cloudflared-quick.service
```

### Tailscale Serve и Funnel

Serve работает только **внутри tailnet** — удобно для браузера на своих
устройствах, но мини-приложение на телефоне без VPN так не открыть.

```bash
sudo tailscale serve --bg --https=443 http://127.0.0.1:8787
```

Funnel формально делает адрес публичным, но публичный DNS Tailscale не выдавал
запись (NXDOMAIN у авторитетных NS `ts.net`, баги tailscale#21502/#21829),
поэтому для мини-приложения он не подошёл.

`TELEGRAM_WEBAPP_URL` в `.env` остаётся запасным адресом: бот использует его,
только если файла туннеля нет.

> Туннель делает панель доступной из интернета. Защита — токен ассистента
> (для мини-приложения ещё и подпись Telegram), но `/shots` (скриншоты)
> отдаётся без авторизации: ссылки содержат случайный суффикс, однако при
> публичном адресе это остаётся риском.

### Вход без пароля

Дашборд внутри Telegram не спросит токен: страница берёт `initData` из
`Telegram.WebApp`, отправляет в `POST /tg/auth`, ядро проверяет подпись
(HMAC-SHA256 на токене бота), сверяет пользователя со списком
`TELEGRAM_ALLOWED_CHAT_IDS` и возвращает токен ассистента.

Что проверяется на стороне ядра:

| Проверка | Результат при провале |
|---|---|
| подпись `hash` совпадает с HMAC на токене бота | 401 «подпись не совпадает» |
| `auth_date` не старше суток | 401 «данные устарели» |
| `TELEGRAM_ALLOWED_CHAT_IDS` задан | 401 «вход запрещён» (fail closed) |
| пользователь в списке разрешённых | 401 «не в списке разрешённых» |

> **Важно:** если `TELEGRAM_ALLOWED_CHAT_IDS` пуст, вход через панель закрыт
> полностью — так же, как и у бота. Список пуст → ничего не выполняется.

> Панель доступна устройствам в домашней сети (локальный HTTPS) и устройствам
> в tailnet (Tailscale Serve). Публиковать её в интернет через Funnel не стоит,
> пока `/shots` (скриншоты) отдаётся без авторизации.

### Вход в браузере

Вне Telegram панель спрашивает **токен ассистента** (`ASSISTANT_TOKEN` из
`.env`). Он сохраняется в localStorage браузера — вводить нужно один раз.
Браузер работает в той же общей сессии, что бот и мини-приложение
(`canonical_session`), поэтому переписка синхронизируется; стереть её можно в
разделе **Ещё** («Очистить историю»).

## Обслуживание

```bash
journalctl -u net-assistant-telegram -f      # логи
sudo systemctl restart net-assistant-telegram
```

Если бот молчит:

1. `systemctl is-active net-assistant-telegram` — процесс жив;
2. в логах `getUpdates` — есть ли доступ к `api.telegram.org` из ВМ;
3. `TELEGRAM_ALLOWED_CHAT_IDS` содержит ваш chat_id;
4. токен не занят другим процессом (Telegram отдаёт `409 Conflict`, если
   один токен опрашивают из двух мест).

## Безопасность

- Токен бота и общий `ASSISTANT_TOKEN` лежат в `.env` (не в git, режим `600`).
- Разрешённые чаты задаются явно; при пустом списке бот не выполняет команды.
- Всё, что бот делает, попадает в журнал ядра: `data/audit.jsonl`.
- Бот и ядро живут на одной машине и общаются по `127.0.0.1`, наружу
  трафик к устройствам не идёт.
- Если токен утёк — BotFather `/revoke` и новый токен в `.env`.
